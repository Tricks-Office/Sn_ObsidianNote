"원고 워드파일로 합쳐줘", "부크크에 낼 워드파일 만들어줘" 같은 요청에 사용한다.
---

## 이 스킬의 범위 (중요)

전자책 출판 준비는 항상 아래 3단계 원칙을 따른다:

1. 원고를 `.md` 파일 형태로 모두 완성한다.
2. **`.md` 파일들을 하나의 `.docx`로 합친다.** 이때 각 장 제목은 워드 서식 "제목 1"/"제목 2"로 지정한다. **이 스킬이 담당하는 부분은 이 2단계뿐이다.**
3. 합쳐진 `.docx`에 **서지정보 삽입과 목차 생성은 워드에서 사용자가 직접** 진행한다. 서지정보를 자동으로 끼워 넣는 이전 시도는 복잡성 대비 효익이 낮다고 판단해 범위에서 뺐고, Word의 "참조 > 목차" 기능은 2단계에서 만든 제목1/제목2 구조를 그대로 읽어 목차를 만들어 주므로 목차 생성은 워드 안에서도 어렵지 않다.

**표지·부 간지·장 표지 이미지는 예외로 이 스킬이 넣는다**(아래 "고급 옵션 5"). 워드에서 이미지를 한 장씩 앉히고 쪽을 나누는 일은 반복이 많고 원고를 다시 합칠 때마다 되풀이해야 하는데, `book-epub`이 이미 같은 설정 필드(`ref_dir`/`cover_image`/`part.image`/`chapters[].image`)를 쓰고 있어 두 산출물을 한 설정으로 맞출 수 있다.

가장 단순한 요청("워드파일로 합쳐줘")도 아래 "기본 진행 방법"을 그대로 따른다 — 설정 JSON에 필수 필드만 채우면 된다. 콜아웃 박스 같은 저자 고유 관습이 있는 프로젝트라면 "고급 옵션" 절에서 해당 필드만 추가로 채운다.

## 사전 확인

- `pandoc`이 설치돼 있어야 하며 최소 버전은 **3.6.4**다(`pandoc --version`). 스크립트도 시작 시 이를 확인해 실패하지만, 미리 안내해두면 사용자가 빠르게 원인을 알 수 있다.
- `기획/2. 책 목차.md`가 있어야 부/장 제목과 순서를 확정할 수 있다.
- 챕터 프런트매터(`소속 부/장:`, `상태:` 등)는 pandoc이 본문에 렌더링하지 않으며, `build_docx.py`도 이를 완전히 버리고 산출물에 다시 넣지 않는다(제목·저자는 오직 설정 파일에서만 가져온다).
- 콜아웃 박스 관습을 쓰는 프로젝트라면(아래 "고급 옵션" 참고), 박스 스타일을 어떻게 표시할지 사용자에게 먼저 확인한다 — 이미 박스용 문단 스타일이 정의된 reference-doc(`.docx`)이 있는지, 없다면 새로 만들지 아니면 스타일 없이 일반 본문으로만 처리할지.

## 검증된 사실

- pandoc으로 markdown의 `#`는 워드의 `Heading1`("제목 1") 스타일로, `##`는 `Heading2`("제목 2")로 매핑된다(표준 동작).
- 여러 `.md` 파일을 한 번에 pandoc에 넘기면 순서·헤더 레벨이 그대로 유지된 채 합쳐진다(실제 확인됨).
- `book-epub`과 달리 프롤로그·에필로그처럼 어느 부에도 속하지 않는 챕터도 **항상** `Heading2`("제목 2")로 매핑된다 — 부 제목만 `Heading1`("제목 1")이다. epub 쪽의 "부에 속하지 않으면 최상위(`#`)" 규칙과 의도적으로 다르다(이 저장소 관례).

## 기본 진행 방법

1. `기획/2. 책 목차.md`(와 있다면 "집필 원칙" 절)를 읽어 부/장 순서, 책 제목·저자, 저자 고유 관습(콜아웃 박스 마커 등) 유무를 확인한다. 불확실하면 사용자에게 묻는다 — 임의로 추측해 설정하지 않는다.
2. 아래 "설정 파일(JSON) 스키마"에 맞춰 설정 파일을 만든다. **원본 프로젝트 폴더가 아니라 스크래치패드 등 임시 위치**에 만든다(원본을 건드리지 않기 위함). `output_path`에 지정할 경로에 이미 파일이 있으면, 스크립트는 확인 없이 그 파일을 곧바로 덮어쓴다(비대화형 CLI라 자체적으로 묻지 않는다) — 그 경로에 파일이 있는지 미리 확인하고, 있으면 덮어써도 되는지 사용자에게 먼저 확인한다. 덮어쓰길 원치 않으면 다른 `output_path`를 정한다.
3. 다음과 같이 스크립트를 호출한다:
   ```
   python "<이 스킬 폴더>/scripts/build_docx.py" --config "<설정 파일 경로>"
   ```
4. 종료 코드가 0이 아니면 "실패 시 종료 코드 안내" 표를 참고해 원인을 사람이 이해할 수 있게 설명하고, 설정을 고쳐 다시 호출한다.
5. 종료 코드가 0이면 표준출력에 찍힌 `.docx` 절대경로를 사용자에게 안내한다. 부 제목은 "제목 1", 장 제목은 "제목 2"로 정확히 매핑됐는지 확인한다(필요하면 docx를 zip으로 열어 `word/document.xml`의 `w:pStyle` 값 확인). 콜아웃 박스를 썼다면 해당 문단에 지정한 스타일이 실제로 적용됐는지도 함께 확인한다.
6. 여기서 멈춘다. 표지·서지정보·목차 삽입은 사용자에게 안내만 하고 직접 하지 않는다 — 위 "이 스킬의 범위" 참고. 원본 `.md`가 항상 원본이다. `.docx`는 파생물이므로 챕터를 고치면 설정 파일로 다시 호출한다.

## 설정 파일(JSON) 스키마

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `schema_version` | 문자열 | 필수 | 정확히 `"1"` |
| `book_title` | 문자열 | 필수 | 책 제목(빈 문자열 불가) |
| `book_author` | 문자열 | 필수 | 저자명(빈 문자열 불가) |
| `src_dir` | 문자열(경로) | 필수 | 챕터 `.md`가 있는 폴더. 절대경로이거나 **이 설정 파일이 있는 폴더 기준 상대경로** |
| `output_path` | 문자열(경로) | 필수 | 만들 `.docx` 경로(확장자 `.docx` 필수, 대소문자 무관). 위와 같은 기준으로 경로 해석 |
| `groups` | 배열 | 필수 | 목차 구조. 아래 "그룹 구조" 참고. 최소 1개 |
| `demote` | 객체 | 선택 | `{"<chapters[].num과 같은 값>": 강등할 레벨 수}`. 챕터 본문에 이미 `###` 등 헤딩이 있어 그대로 두면 부/장 구조와 섞일 때 사용 |
| `source_heading_pattern` | 문자열(정규식) 또는 `null` | 선택 | 이 정규식과 일치하는 줄(주로 "### 출처(...)" 같은 라벨 헤딩)을 통째로 삭제. 각주 자체는 그대로 남는다(단, docx에서는 각주 본문이 `word/footnotes.xml`이라는 별도 파트에 들어간다 — 워드에서 열면 정상적인 각주로 보인다) |
| `extract_fenced_tables` | 불리언 | 선택 | 코드펜스로 인용한 다른 문서 안에 마크다운 표가 있으면 `true` — 표만 뽑아 실제 워드 표로 만든다 |
| `content_image_dir` | 문자열(경로) 또는 `null` | 선택 | 본문 삽입 이미지 폴더(보통 `본문/이미지`, `book-epub`과 동일한 폴더 재사용 가능). 챕터 안에서는 `이미지/파일명.png`로 참조 |
| `ref_dir` | 문자열(경로) 또는 `null` | 선택 | 표지·간지 이미지가 든 폴더 — 아래 "고급 옵션 5" 참고. 이미지를 하나라도 쓰면 필수 |
| `cover_image` | 문자열 또는 `null` | 선택 | 표지 이미지 — `ref_dir` 바로 아래의 **파일명만**(경로 구분자 불가) |
| `box_marker` | 문자열 또는 `null` | 선택 | 콜아웃 박스 코드펜스 마커 단어(예: `"박스"`) — 아래 "고급 옵션 1" 참고. 지정하려면 `box_style_name`·`reference_doc`도 함께 지정해야 한다 |
| `box_style_name` | 문자열 또는 `null` | 조건부 | `custom-style`로 지정할 워드 문단 스타일 이름. `box_marker`를 쓰면 필수 |
| `reference_doc` | 문자열(경로) 또는 `null` | 조건부 | `box_style_name`에 지정한 스타일이 정의된 참조 `.docx`. `box_marker`를 쓰면 필수 |

`box_marker`/`box_style_name`/`reference_doc`는 **셋 다 설정하거나 셋 다 비워야** 한다(하나만 채우면 오류). `ref_dir`/`cover_image`와 `groups[].part.image`/`groups[].chapters[].image`는 `book-epub`과 **이름·의미가 같다** — 두 산출물을 한 설정에서 맞추라고 일부러 같은 이름을 쓴다(아래 "고급 옵션 5"). 반면 `book-epub`의 `use_toc_hierarchy`/`colophon_src`/`colophon_unlisted`/`extra_css`/`identifier`는 이 스킬에 **없다** — docx는 판권 페이지·커스텀 CSS·목차 계층 옵션·안정적 식별자를 지원하지 않는다(위 "이 스킬의 범위" 참고).

### 그룹 구조 (`groups`)

`groups`는 배열이고, 각 원소는 `{"part": ..., "chapters": [...]}` 형태다.

- `part`가 `null`이면 어느 부에도 속하지 않는 챕터(프롤로그·에필로그·부록 등)의 그룹이다.
- `part`가 객체면 `{"title": "부 제목", "image": "파일명 또는 null"}` — 그 부에 속한 장들을 `chapters`에 나열한다.
- `chapters`의 각 원소: `{"num": "장 번호(파일명 규칙과 동일)", "title": "장 제목", "image": "파일명 또는 null"}`. `num`은 `본문/` 폴더에서 `*_<num>장_*.md` 또는 `*<num>*.md` 패턴으로 파일을 찾는 데 쓰인다 — 정확히 1개가 매치되지 않으면 실패한다. **`num`은 책 전체에서 유일해야 한다.** 부마다 장 번호가 `01`부터 다시 시작하는 파일명 규칙(`<책>_1부_01장_….md`, `<책>_2부_01장_….md`)을 쓴다면 `"01"`로는 두 파일이 매치되거나(오류 5) 번호가 중복되므로(오류 6), **부 자리를 포함한 값**을 쓴다 — `"1부_01"`, `"2부_01"`, `"0프롤로그_00"`, `"9에필로그_00"`. `demote`의 키도 여기서 쓴 값과 똑같이 적는다.

예시(프롤로그 + 1부 아래 2개 장):
```json
{
  "schema_version": "1",
  "book_title": "제목",
  "book_author": "저자",
  "src_dir": "본문",
  "output_path": "출판/책_원고.docx",
  "groups": [
    {"part": null, "chapters": [{"num": "0프롤로그_00", "title": "프롤로그"}]},
    {"part": {"title": "1부 · 부 제목"},
     "chapters": [
       {"num": "1부_01", "title": "1장 · 장 제목"},
       {"num": "1부_02", "title": "2장 · 장 제목"}
     ]}
  ]
}
```

## 고급 옵션 — 필요한 필드만 채운다

프로젝트에 해당 관습이 있는지 사용자에게 먼저 확인한 뒤에만 채운다.

### 1. 저자 고유의 콜아웃 박스 관습 (예: 코드펜스 ```박스)

`book-epub` 스킬과 동일한 관습이다 — 박스에 넣을 내용을 코드펜스로 감싸고, 코드펜스의 정보 문자열에 마커 단어를 적는다. 예를 들어 마커가 "박스"라면 원본 `.md`에는 다음과 같이 쓴다:

````
```박스
글상자에 들어갈 내용
```
````

워드는 CSS가 없으므로 `book-epub`처럼 `class`로 스타일을 주는 방식이 통하지 않는다. 대신 pandoc이 지원하는 **`custom-style`** 속성으로 워드 문단 스타일을 지정한다 — 스크립트가 코드펜스 안 내용을 `::: {custom-style="<box_style_name>"} ... :::`로 자동 변환한다.

`custom-style`을 쓰려면 다음을 채운다:
- `box_marker`: 코드펜스 마커 단어(예: `"박스"`)
- `box_style_name`: 워드 문단 스타일 이름
- `reference_doc`: 그 스타일이 정의된 참조 `.docx` 경로

`box_style_name`의 이름을 가진 문단 스타일이 `reference_doc`에 **미리 정의되어 있어야** 한다 — 이 스킬이 스타일 자체를 만들어주지는 않는다. 없다면 사용자에게 다음을 안내한다: 워드에서 새 문서를 열고, 홈 > 스타일 갤러리에서 "새 스타일" 만들기 → 원하는 이름(예: "박스")으로 저장 → 문단 테두리·음영·여백 등 박스처럼 보이게 서식 지정 → 그 스타일을 최소 한 문단에 적용한 뒤 `.docx`로 저장. (참고: `reference_doc`에 스타일이 실제로 없어도 pandoc이 `Normal`을 상속한 스타일을 그 이름으로 새로 만들어 적용하기는 하지만, 그 경우 테두리·음영 같은 시각적 구분은 생기지 않는다 — 실제로 구분되는 박스를 원하면 스타일을 미리 정의해야 한다.)

**본문 중에 우연히 같은 문구가 들어간 일반 문장**까지 잘못 건드리지 않도록, 마커는 코드펜스의 정보 문자열로만 인식한다(줄 단위 프로즈 매칭을 쓰지 않는다) — `book-epub`에서 이미 검증된 것과 같은 이유다.

### 2. 본문 중간에 실제 콘텐츠 이미지 삽입 (삽화, 스크린샷 등)

`content_image_dir`에 이미지 폴더 경로(보통 `본문/이미지`)를 채운다. 챕터 원본 `.md`에는 표준 마크다운 이미지 문법을 그대로 쓴다(`book-epub`과 동일한 규칙, 폴더를 공유할 수 있다):
```
![대체 텍스트 — 이미지 내용을 설명](이미지/08_01.png)
```

### 3. 각주/출처 헤딩의 라벨만 숨기기

챕터 끝에 "### 출처(참고문헌, 영상, Web)" 같은 라벨 헤딩 다음에 pandoc 각주 정의(`[^1]: ...`)만 있는 구조라면, 실제 라벨 문구에 맞는 정규식을 `source_heading_pattern`에 넣는다(예: `"^#{1,6}\\s*출처\\(참고문헌, 영상, Web\\)\\s*$"`).

### 4. 코드펜스 안에 마크다운 표가 있는 경우

`extract_fenced_tables`를 `true`로 켠다(다른 문서를 코드블록으로 통째로 인용하는 부록 등에서 유용).

### 5. 표지 / 부 간지 / 장 표지 이미지
`ref_dir`에 이미지가 든 폴더를 넣고, 쓰고 싶은 자리에 파일명을 적는다. 셋 다 선택이고 필요한 것만 쓰면 된다.

- **표지** — `cover_image`. 문서 맨 앞에 이미지만 한 쪽으로 들어간다. **헤딩을 붙이지 않는다** — 붙이면 워드의 "참조 > 목차" 첫 줄에 "표지"가 끼어든다.
- **부 간지** — `groups[].part.image`. **부 제목("제목 1")은 지우지 않고 그대로 두고**, 그 아래에 이미지를 놓는다. 제목을 지우면 워드 자동 목차에서 그 부가 통째로 사라지기 때문이다. `book-epub`이 부 제목을 감추고 이미지로 대체하는 것과 여기가 다르다.
- **장 표지** — `groups[].chapters[].image`. 장 제목("제목 2") **앞에** 이미지가 들어간다.

이미지마다 바로 뒤에 쪽 나누기(raw OpenXML `<w:br w:type="page"/>`)를 넣어 다음 내용이 같은 쪽에 붙지 않게 한다. 워드에는 epub의 "표지 전용 페이지" 같은 개념이 없어 쪽을 직접 끊어야 한다.

이미지 파일은 모두 `ref_dir` **바로 아래**에 있어야 하고 파일명만 적는다(경로 구분자 불가). 하나라도 쓰면서 `ref_dir`을 빠뜨리면 스키마 오류(4), `ref_dir`에 그 파일이 없으면 경로 오류(5)로 빌드 전에 걸린다.

`content_image_dir`(본문 중간 삽화)과는 **별개 필드**다. 같은 폴더를 둘 다에 지정해도 된다.

## 실패 시 종료 코드 안내

스크립트는 실패하면 0이 아닌 종료 코드와 stderr 메시지를 낸다. 아무 것도 만들지 않거나(원래 없었으면) 기존 `output_path` 파일을 그대로 둔다(있었으면) — 실패한 실행이 기존 결과물을 훼손하지 않는다.

| 종료 코드 | 의미 | 사용자에게 안내할 방향 |
|---|---|---|
| 2 | `--config` 경로가 없음 | 설정 파일 경로를 다시 확인 |
| 3 | 설정 파일을 읽을 수 없거나 JSON이 아님 | JSON 문법 오류 수정 |
| 4 | 스키마 오류(필수 필드 누락, 미정의 키 — `book-epub` 전용 필드 포함, 빈 문자열, 확장자 오류, `output_path`가 입력 파일과 충돌 등) | 메시지가 가리키는 필드를 고침 |
| 5 | 참조 경로가 실제로 없음(챕터 파일, `content_image_dir`, `reference_doc` 등) | 경로 확인 |
| 6 | 목차 구조 모순(장 번호 중복, `demote`가 없는 장을 가리킴 등) | `groups`/`demote` 수정 |
| 7 | `box_marker`/`box_style_name`/`reference_doc` 중 일부만 지정됨 | 셋 다 채우거나 셋 다 비움 |
| 8 | pandoc이 없거나 버전이 3.6.4 미만 | pandoc 설치/업그레이드 안내 |
| 9 | pandoc 자체가 실패 | stderr에 담긴 pandoc 원인 메시지 확인 |
| 10 | `output_path`에 쓸 수 없음(권한 등) | 출력 경로/권한 확인 |
| 11 | 그 외 파일 읽기/쓰기 오류(예: 챕터 파일이 UTF-8이 아님) | 메시지가 가리키는 파일 확인 |
| 12 | pandoc은 성공했지만 최종 파일 교체에 실패 | 메시지에 나온 임시 파일 경로에서 결과물을 수동으로 복구 |
| 13 | pandoc 호출이 120초를 넘겨 시간 초과 | 재시도, 반복되면 pandoc/환경 점검 |

## 주의사항

- 표지·서지정보·목차 자동 삽입을 다시 시도하지 않는다 — 의도적으로 범위 밖에 둔 결정이다.
- 챕터 순서를 파일 시스템의 기본 정렬만 믿고 정하지 않는다 — 반드시 목차와 대조해 `groups`를 구성한다.
- 콜아웃 박스용 워드 스타일 자체를 자동으로 만들어주지 않는다 — 항상 사용자의 `reference_doc`에 이미 정의된 스타일 이름을 그대로 가져다 쓴다.
- 위 고급 옵션은 모두 **선택적**이다 — 프로젝트에 해당 관습이 없으면 억지로 채우지 않는다.
- 설정 파일은 원본 프로젝트 폴더가 아니라 스크래치패드 등 임시 위치에 만든다.
