---

## 언제 사용하나

사용자가 회의 중/후에 남긴 메모, 대화 내용, 녹취 요약 등을 `Template/회의록.md` 양식에 맞춰 정리해 프로젝트 폴더에 노트로 저장하고 싶을 때 사용한다.

## 저장 위치와 파일명

1. **대상 프로젝트 확인:** 어느 프로젝트(`1. Project/<프로젝트명>/`)의 회의인지 먼저 확인한다. 진행 중인 프로젝트가 대화 맥락상 하나뿐이면 굳이 묻지 않아도 된다.
2. **경로:** `1. Project/<프로젝트명>/회의록/YYYY-MM-DD 회의록.md`
   - 같은 날 회의가 여러 건이면 `YYYY-MM-DD 회의록 - <구분자>.md`처럼 구분자를 붙인다(예: 안건명, 몇 차 회의인지).
   - 프로젝트에 이미 다른 회의록 저장 관례(예: 폴더 없이 프로젝트 루트에 바로 저장)가 있으면 새 규칙을 강제하지 않고 기존 관례를 따른다.
3. 책쓰기 프로젝트(`1. Project/집필/<책 이름>/`)의 회의록은 그 프로젝트가 별도의 로컬 전용 git 저장소이므로, 해당 프로젝트 폴더 규칙(있다면)을 우선 확인한다.

## 정리 방법

1. `Template/회의록.md`를 그대로 복사해 구조와 frontmatter를 시작점으로 쓴다.
2. 사용자가 준 원문(대화 로그, 메모, 녹취 요약 등)에서 다음 7개 섹션으로 정보를 배분한다. 없는 정보는 빈칸으로 두지 말고 "해당 없음" 대신 자연스럽게 생략하되 헤더 자체는 유지한다.
   - **일시**: 회의 날짜(및 가능하면 시간). 원문에 없으면 사용자에게 확인한다.
   - **참석자**: 언급된 이름/역할을 나열.
   - **안건**: 회의에서 다루기로 한 주제 목록.
   - **논의 내용**: 안건별로 오간 논의를 압축해서 정리한다(발언을 그대로 옮겨 적지 않고, 핵심만 자기 언어로 압축 — 이 벡터의 압축 원칙과 동일).
   - **결정 사항**: 논의 결과 확정된 것만 적는다. 논의는 됐지만 결정되지 않은 건 "논의 내용"에 남기고 여기 넣지 않는다.
   - **액션 아이템**: 담당자·할 일·기한이 표에 들어가도록 정리한다. 담당자나 기한이 원문에 없으면 셀을 비워두고, 필요하면 사용자에게 확인한다.
   - **제약 사항**: 회의록 작성 시 지켜야 할 제약 사항을 안내한다.
3. 원문에서 애매하거나 상충하는 내용(예: 결정 사항인지 논의 중인 안건인지 불분명)이 있으면 넘기지 말고 사용자에게 확인한다 — 추측해서 채우지 않는다.
4. `write date`/`edit date`를 생성 시각으로 동일하게 채운다.

## 기존 회의록 수정하기

- 같은 회의에 대한 추가 내용(누락된 액션 아이템, 추가 결정 등)을 반영하는 것이라면 새 파일을 만들지 말고 기존 파일을 수정하고, `edit date`만 현재 시각으로 갱신한다(`write date`는 유지).
- 완전히 다른 회의라면 새 파일로 분리한다.

## 저장 전 체크리스트

- [ ] frontmatter가 `write date`/`edit date`/`tags`/`type: meeting-minutes`/`links` 다섯 필드를 갖췄는가
- [ ] 7개 섹션(일시/참석자/안건/논의 내용/결정 사항/액션 아이템/제약 사항) 헤더가 모두 있는가
- [ ] "결정 사항"에 미확정 논의가 섞여 들어가지 않았는가
- [ ] 액션 아이템 표의 담당자·기한 중 원문에 없는데 임의로 지어낸 값이 없는가

## 주의사항

- `Template/회의록.md`는 원본 템플릿이므로 직접 덮어쓰지 않는다 — 항상 새 회의록 파일로 복사해서 쓴다.
- 이 스킬은 회의 내용을 "압축·정리"하는 것이지 "창작"하는 게 아니다. 원문에 없는 결정이나 액션 아이템을 추측해서 채우지 않는다.
