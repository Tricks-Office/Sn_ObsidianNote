## 언제 사용하나

본문 챕터들의 초고/퇴고가 끝나 실제 전자책 파일(`.epub`)로 확인하거나 배포하고 싶을 때 사용한다. 출판사 투고용 `.docx`(`투고/` 폴더, 챕터 1개씩 개별 변환)와는 목적이 다르다 — 이 스킬은 여러 챕터를 목차 순서대로 합쳐 독자가 바로 읽을 수 있는 한 권짜리 파일을 만드는 것이다.

가장 단순한 요청("epub 만들어줘")도 아래 "기본 진행 방법"을 그대로 따른다 — 설정 JSON에 필수 필드만 채우면 된다. 표지·박스·목차 계층 같은 요청이 나오면 "고급 옵션" 절에서 해당 필드만 추가로 채운다.

## 사전 확인

- `pandoc`이 설치돼 있어야 하며 최소 버전은 **3.6.4**다(`pandoc --version`). 스크립트도 시작 시 이를 확인해 실패하지만, 미리 안내해두면 사용자가 빠르게 원인을 알 수 있다. pandoc이 아예 없다면 설치를 안내하고 중단한다 — 검증되지 않은 다른 변환 방법으로 우회하지 않는다.
- pandoc의 markdown 리더는 파일 맨 위 YAML frontmatter를 메타데이터로만 인식하고 본문에 렌더링하지 않는다. 이 프로젝트의 챕터 프런트매터에 있는 `소속 부/장`, `상태`, `핵심 주장` 같은 확장 필드도 본문에 새지 않는다 — 실제로 확인된 사실이며 별도 처리가 필요 없다. `build_epub.py`는 이 프런트매터를 아예 버리고 산출물에 절대 다시 넣지 않는다(제목·저자는 오직 설정 파일에서만 가져온다).

## 기본 진행 방법

1. `기획/`의 목차 문서(와 있다면 "집필 원칙" 절)를 읽어 부/장 순서, 책 제목·저자, 저자 고유 관습(콜아웃 박스 마커, 출처 라벨 문구 등) 유무를 확인한다. 불확실하면 사용자에게 묻는다 — 임의로 추측해 설정하지 않는다.
2. 아래 "설정 파일(JSON) 스키마"에 맞춰 설정 파일을 만든다. **원본 프로젝트 폴더가 아니라 스크래치패드 등 임시 위치**에 만든다(원본을 건드리지 않기 위함). `output_path`에 지정할 경로에 이미 파일이 있으면, 스크립트는 확인 없이 그 파일을 곧바로 덮어쓴다(비대화형 CLI라 자체적으로 묻지 않는다) — 그 경로에 파일이 있는지 미리 확인하고, 있으면 덮어써도 되는지 사용자에게 먼저 확인한다. 덮어쓰길 원치 않으면 다른 `output_path`를 정한다.
3. 다음과 같이 스크립트를 호출한다:
   ```
   python "<이 스킬 폴더>/scripts/build_epub.py" --config "<설정 파일 경로>"
   ```
4. 종료 코드가 0이 아니면 "실패 시 종료 코드 안내" 표를 참고해 원인을 사람이 이해할 수 있게 설명하고, 설정을 고쳐 다시 호출한다. 스크립트의 원문 stderr 메시지를 그대로 보여줘도 되지만, 무엇을 고쳐야 하는지 한국어로 요약해 덧붙인다.
5. 종료 코드가 0이면 표준출력에 찍힌 `.epub` 절대경로를 사용자에게 안내한다. 목차·챕터 순서·표지가 의도대로 보이는지는 실제 전자책 리더 앱(예: Calibre, 각 OS 기본 리더)으로 열어 사용자에게 직접 확인을 요청한다 — 변환이 성공했다는 것과 사용자의 기기에서 읽기 편하다는 것은 다른 문제다.
6. 원본 `.md`가 항상 원본이다. `.epub`은 파생물이므로 챕터를 고치면 설정 파일로 다시 호출한다.

## 설정 파일(JSON) 스키마

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `schema_version` | 문자열 | 필수 | 정확히 `"1"` |
| `book_title` | 문자열 | 필수 | 책 제목(빈 문자열 불가) |
| `book_author` | 문자열 | 필수 | 저자명(빈 문자열 불가) |
| `language` | 문자열 | 선택 | 책의 언어 태그(BCP 47). 생략하면 `"ko-KR"`. 빈 문자열 불가 — 다른 언어로 낼 때만 `"en-US"` 등으로 바꾼다 |
| `src_dir` | 문자열(경로) | 필수 | 챕터 `.md`가 있는 폴더. 절대경로이거나 **이 설정 파일이 있는 폴더 기준 상대경로** |
| `output_path` | 문자열(경로) | 필수 | 만들 `.epub` 경로(확장자 `.epub` 필수, 대소문자 무관). 위와 같은 기준으로 경로 해석 |
| `groups` | 배열 | 필수 | 목차 구조. 아래 "그룹 구조" 참고. 최소 1개 |
| `demote` | 객체 | 선택 | `{"<chapters[].num과 같은 값>": 강등할 레벨 수}`. 챕터 본문에 이미 `##` 등 헤딩이 있어 그대로 두면 목차를 오염시킬 때 사용 |
| `source_heading_pattern` | 문자열(정규식) 또는 `null` | 선택 | 이 정규식과 일치하는 줄(주로 "### 출처(...)" 같은 라벨 헤딩)을 통째로 삭제. 각주 자체는 그대로 남는다 |
| `extract_fenced_tables` | 불리언 | 선택 | 코드펜스로 인용한 다른 문서 안에 마크다운 표가 있으면 `true` — 표만 뽑아 실제 `<table>`로 만든다 |
| `content_image_dir` | 문자열(경로) 또는 `null` | 선택 | 본문 삽입 이미지 폴더(보통 `본문/이미지`). 챕터 안에서는 `이미지/파일명.png`로 참조 |
| `box_marker` | 문자열 또는 `null` | 선택 | 콜아웃 박스 코드펜스 마커 단어(예: `"박스"`) — 아래 "고급 옵션 3" 참고 |
| `ref_dir` | 문자열(경로) 또는 `null` | 조건부 | 표지·부 표지·챕터 표지 이미지가 있는 폴더. 아래 셋 중 하나라도 쓰면 필수 |
| `cover_image` | 문자열 또는 `null` | 선택 | epub 표지 이미지 — `ref_dir` 바로 아래의 **파일명만**(경로 구분자 불가) |
| `use_toc_hierarchy` | 불리언 또는 `null` | 선택 | 부/장 목차 계층 사용 여부. 생략하면 `groups`에 `part`가 하나라도 있으면 자동으로 `true` |
| `colophon_src` | 문자열(경로) 또는 `null` | 선택 | 판권/서지 페이지로 이어붙일 `.md` 파일 |
| `colophon_unlisted` | 불리언 | 선택 | 판권 페이지를 목차에서 감출지(기본 `false`) |
| `extra_css` | 문자열 | 선택 | pandoc 기본 CSS + 스킬 고정 규칙 뒤에 추가할 커스텀 CSS(기본 빈 문자열) |
| `identifier` | 문자열 또는 `null` | 선택 | epub 식별자. 생략하면 pandoc이 빌드마다 새 UUID를 생성한다(재실행 시 이 필드만 값이 달라짐) |

### 그룹 구조 (`groups`)

`groups`는 배열이고, 각 원소는 `{"part": ..., "chapters": [...]}` 형태다.

- `part`가 `null`이면 어느 부에도 속하지 않는 챕터(프롤로그·에필로그·부록 등)의 그룹이다.
- `part`가 객체면 `{"title": "부 제목", "image": "파일명 또는 null"}` — 그 부에 속한 장들을 `chapters`에 나열한다.
- `chapters`의 각 원소: `{"num": "장 번호(파일명 규칙과 동일)", "title": "장 제목", "image": "파일명 또는 null"}`. `num`은 `본문/` 폴더에서 `*_<num>장_*.md` 또는 `*<num>*.md` 패턴으로 파일을 찾는 데 쓰인다 — 정확히 1개가 매치되지 않으면 실패한다. **`num`은 책 전체에서 유일해야 한다.** 부마다 장 번호가 `01`부터 다시 시작하는 파일명 규칙(`<책>_1부_01장_….md`, `<책>_2부_01장_….md`)을 쓴다면 `"01"`로는 두 파일이 매치되거나(오류 5) 번호가 중복되므로(오류 6), **부 자리를 포함한 값**을 쓴다 — `"1부_01"`, `"2부_01"`, `"0프롤로그_00"`, `"9에필로그_00"`. `demote`의 키도 여기서 쓴 값과 똑같이 적는다.

예시(프롤로그 + 1부 아래 2개 장):
```json
{
  "schema_version": "1",
  "book_title": "제목",
  "book_author": "저자",
  "src_dir": "본문",
  "output_path": "출판/책.epub",
  "groups": [
    {"part": null, "chapters": [{"num": "0프롤로그_00", "title": "프롤로그", "image": null}]},
    {"part": {"title": "1부 · 부 제목", "image": null},
     "chapters": [
       {"num": "1부_01", "title": "1장 · 장 제목", "image": null},
       {"num": "1부_02", "title": "2장 · 장 제목", "image": null}
     ]}
  ]
}
```

## 고급 옵션 — 필요한 필드만 채운다

프로젝트에 해당 관습이 있는지 사용자에게 먼저 확인한 뒤에만 채운다. 임의로 추측해서 설정하지 않는다.

### 1. 표지 이미지
`ref_dir`(이미지가 있는 폴더)과 `cover_image`(그 폴더 안 파일명)를 채운다.

표지 지정 방식은 두 가지이고 **스크립트가 둘 다 넣는다.** pandoc은 EPUB3 방식(manifest 항목의 `properties="cover-image"`)만 쓰는데, 그것만 있으면 **리더 앱이나 서점에 따라 표지가 안 보인다** — 구형 메타 `<meta name="cover" content="…"/>`를 봐야 표지를 찾는 곳이 있기 때문이다(Sigil에서 이미지에 "Cover" 의미를 지정하면 하는 일이 이것이다). 그래서 pandoc이 끝난 뒤 `add_legacy_cover_meta()`가 OPF 메타데이터에 그 한 줄을 넣는다. 이미 들어 있으면 건드리지 않고, `cover_image`가 없으면 실행되지 않는다. 별도 설정은 필요 없다.

### 2. 부 표지 / 챕터 표지("이 페이지엔 이미지만")
- 부 제목 대신 이미지만 보이게 하려면: 그 그룹의 `part.image`에 파일명을 넣는다(부 제목 텍스트는 목차에 그대로 남고 화면에서만 이미지로 대체됨).
- 프롤로그/에필로그/부록처럼 "표지 이미지 페이지 + 그다음 진짜 제목 페이지"를 원하면: 해당 챕터의 `chapters[].image`에 파일명을 넣는다(표지 페이지는 목차에서 자동으로 숨겨진다).
- 표지·부 표지·챕터 표지 이미지는 모두 `ref_dir` 폴더 바로 아래에 있어야 한다.

### 3. 저자 고유의 콜아웃 박스 관습 (예: 코드펜스 ```박스)
`box_marker`에 마커 단어(예: `"박스"`)를 넣는다. 그러면 원본 `.md`에 다음과 같이 쓰인 코드펜스를 스크립트가 자동으로 콜아웃 박스로 바꾼다:
````
```박스
글상자에 들어갈 내용
```
````
코드펜스는 pandoc이 내부를 마크다운으로 파싱하지 않는 유일한 구문이라 여는/닫는 펜스 자체가 박스의 시작과 끝을 명확히 표시한다 — 본문 중 우연히 같은 문구가 나와도 코드펜스가 아니면 절대 매칭되지 않는다. 박스 안에 제목이 필요하면 첫 줄에 헤딩(`#### 제목`)을 그냥 적으면 된다.

### 4. 각주/출처 헤딩의 라벨만 숨기기
챕터 끝에 "### 출처(참고문헌, 영상, Web)" 같은 라벨 헤딩 다음에 pandoc 각주 정의(`[^1]: ...`)만 있는 구조라면, 실제 라벨 문구에 맞는 정규식을 `source_heading_pattern`에 넣는다(예: `"^#{1,6}\\s*출처\\(참고문헌, 영상, Web\\)\\s*$"`). 각주 자체는 스크립트가 지우지 않는다 — 라벨 줄만 빠지고 각주와 본문 사이의 연결은 그대로 남는다. 챕터별로 변환하므로 각주 본문은 해당 장의 XHTML에 남으며, 책 끝의 통합 미주로 모이지 않는다(표시 방식은 리더 앱마다 다르다).

### 5. 목차 계층 — 부(큰 항목) / 장(작은 항목)
`groups`에 `part`가 하나라도 있으면 `use_toc_hierarchy`는 자동으로 켜진다(명시적으로 `false`로 끌 수도 있음). 부 제목은 항상 최상위, 그 부에 속한 장은 한 단계 들여쓰기된다.

### 6. 본문 중간에 실제 콘텐츠 이미지 삽입 (삽화, 스크린샷 등)
`content_image_dir`에 이미지 폴더 경로(보통 `본문/이미지`)를 채운다. 챕터 원본 `.md`에는 표준 마크다운 이미지 문법을 그대로 쓴다:
```
![대체 텍스트 — 이미지 내용을 설명](이미지/08_01.png)
```
- Obsidian에서 그대로 미리보기가 되므로, 본문 자체가 삽입 위치 표시를 겸한다.
- `book-docx` 스킬도 같은 폴더·같은 상대경로 규칙을 재사용한다 — 이미지를 한 번만 준비하면 양쪽 빌드가 같은 소스를 그대로 쓴다.

### 7. 책 맨 끝에 판권/서지 페이지 추가
`colophon_src`에 서지정보 `.md` 파일 경로를 채운다. 목차에 노출할지는 사용자에게 확인한 뒤 `colophon_unlisted`로 정한다.

### 8. 코드펜스 안에 마크다운 표가 있는 경우
`extract_fenced_tables`를 `true`로 켠다(다른 문서를 코드블록으로 통째로 인용하는 부록 등에서 유용).

### 9. 커스텀 CSS 추가
`extra_css`에 원하는 CSS 규칙을 그대로 문자열로 넣는다. `--css`가 pandoc 기본 스타일시트를 통째로 지워버리는 함정은 스크립트가 내부적으로(기본 스타일시트 + 스킬 고정 규칙 + `extra_css` 순서로 결합) 처리하므로 신경 쓰지 않아도 된다.

## 실패 시 종료 코드 안내

스크립트는 실패하면 0이 아닌 종료 코드와 stderr 메시지를 낸다. 아무 것도 만들지 않거나(원래 없었으면) 기존 `output_path` 파일을 그대로 둔다(있었으면) — 실패한 실행이 기존 결과물을 훼손하지 않는다.

| 종료 코드 | 의미 | 사용자에게 안내할 방향 |
|---|---|---|
| 2 | `--config` 경로가 없음 | 설정 파일 경로를 다시 확인 |
| 3 | 설정 파일을 읽을 수 없거나 JSON이 아님 | JSON 문법 오류 수정 |
| 4 | 스키마 오류(필수 필드 누락, 미정의 키, 빈 문자열, 확장자 오류, 이미지 파일명 규칙 위반, `output_path`가 입력 파일과 충돌 등) | 메시지가 가리키는 필드를 고침 |
| 5 | 참조 경로가 실제로 없음(챕터 파일, 이미지, `ref_dir`, `content_image_dir`, `colophon_src` 등) | 경로·파일명 확인 |
| 6 | 목차 구조 모순(장 번호 중복, `demote`가 없는 장을 가리킴 등) | `groups`/`demote` 수정 |
| 8 | pandoc이 없거나 버전이 3.6.4 미만 | pandoc 설치/업그레이드 안내 |
| 9 | pandoc 자체가 실패 | stderr에 담긴 pandoc 원인 메시지 확인 |
| 10 | `output_path`에 쓸 수 없음(권한 등) | 출력 경로/권한 확인 |
| 11 | 그 외 파일 읽기/쓰기 오류(예: 챕터 파일이 UTF-8이 아님) | 메시지가 가리키는 파일 확인 |
| 12 | pandoc은 성공했지만 최종 파일 교체에 실패 | 메시지에 나온 임시 파일 경로에서 결과물을 수동으로 복구 |
| 13 | pandoc 호출이 120초를 넘겨 시간 초과 | 재시도, 반복되면 pandoc/환경 점검 |

## 검증된 사실

- pandoc에 `lang`을 넘기지 않으면 epub 메타데이터의 언어가 **`en-US`로 박힌다**(실측). 읽는 데는 지장이 없지만 리더의 줄바꿈·글꼴 선택과 일부 플랫폼 검수에서 걸리는 값이라, `build_epub.py`는 `language`를 항상 `--metadata lang=`으로 넘기고 생략 시 `ko-KR`을 쓴다.
- 여러 `.md` 파일을 한 번에 pandoc에 넘기면 순서·헤더 레벨이 그대로 유지된 채 합쳐진다.
- 각 챕터가 `[^1]`부터 다시 매기는 각주를 쓰더라도(장마다 번호가 초기화) 스크립트가 항상 `--file-scope`를 붙이므로 파일별로 따로 파싱되어 각주가 자동으로 재번호된다.
- 콜아웃 박스나 챕터 표지처럼 `.unlisted` 헤딩 바로 뒤에 실제 장 제목 헤딩이 이어지는 구조에서는, 둘의 헤딩 레벨이 같아야 한다 — 표지 헤딩이 실제 제목보다 얕은 레벨(예: 표지는 h1, 실제 제목은 h2)이면 pandoc이 실제 제목을 표지의 하위 섹션으로 취급해서, 표지가 `.unlisted`일 때 실제 제목까지 목차에서 통째로 사라진다(실측으로 확인됨). 이 스킬의 `build_epub.py`는 항상 같은 레벨을 쓰도록 구현되어 있다.

## 주의사항

- pandoc이 없다고 수동으로 zip을 조립하는 등 다른 방식으로 우회하지 않는다 — 검증되지 않은 결과물을 만들 위험이 크다.
- 챕터 순서를 파일 시스템의 기본 정렬만 믿고 정하지 않는다 — 반드시 목차와 대조해 `groups`를 구성한다.
- **줄간격은 설정 없이 기본으로 들어간다.** pandoc 기본 CSS는 `html { line-height: 1.2 }`라 한글 본문을 **전자책 단말기로 읽으면 답답하다.** 그래서 기본 CSS 뒤에 줄간격 규칙을 붙인다 — 본문·목록·표는 150%, 장 제목(h1) 170%, 부 제목(h2) 160%. 실제 단말기에서 확인한 값이다. `line-height`만 다시 지정하고 여백 규칙은 건드리지 않는다(뒤에 붙는 규칙이 앞의 `margin`까지 덮으면 제목·목록 간격이 무너진다). 더 넓히거나 좁히려면 `extra_css`에 값을 넣으면 된다 — 그쪽이 더 뒤에 붙으므로 이긴다.
- 위 고급 옵션은 모두 **선택적**이다 — 프로젝트에 해당 요소(표지, 박스 관습, 콘텐츠 이미지 등)가 없다면 억지로 채우지 않는다. 특히 박스 마커나 이미지 파일명은 사용자가 실제로 쓰는 관습을 먼저 확인하고 채운다.
- 설정 파일은 원본 프로젝트 폴더가 아니라 스크래치패드 등 임시 위치에 만든다.
- ISBN, 플랫폼별 제출 조건은 이 스킬의 범위를 벗어난다.
