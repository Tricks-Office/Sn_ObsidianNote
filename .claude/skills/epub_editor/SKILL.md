## 개요

이 스킬은 `scripts/epub_tool.py`의 `extract`(epub → 편집용 폴더)와 `pack`(편집용 폴더 →
epub) 두 서브커맨드로 동작한다. 스크립트는 **비대화형**이며 사용자 확인이 필요한 모든 분기
(폴더 충돌, 덮어쓰기)를 스스로 묻지 않고 실패로 끝난다 — Claude가 그 실패를 해석해 사용자에게
먼저 질문하고, 확정된 옵션(`--force`, `--dest-name`)으로 스크립트를 다시 호출해야 한다. 스크립트를
`--force`로 재호출하는 것 외의 어떤 이유로도 스크립트가 실패를 반환했을 때 자동으로 다른 옵션
조합을 계속 시도하지 않는다 — 원인을 그대로 사용자에게 보여주고 다음 지시를 기다린다.

스크립트 경로: `scripts/epub_tool.py`(이 SKILL.md와 같은 폴더 아래). 항상 절대경로 또는
현재 스킬 폴더 기준 상대경로로 호출한다.

## 1. epub 압축 해제(편집 시작)

1. 편집할 대상 epub 파일의 경로를 확인한다(사용자가 선택했거나 명시한 파일).
2. 먼저 `--force` 없이 실행한다:
   ```
   python <스킬폴더>/scripts/epub_tool.py extract "<epub_path>"
   ```
3. 종료 코드에 따라 처리한다:
   - **0(성공)**: stdout에 출력된 폴더 경로를 확인하고 §2로 진행한다.
   - **7(폴더 이미 존재)**: stderr 메시지에 포함된 절대경로와 비어있지 않음 여부를 사용자에게
     보여주고, "기존 폴더를 삭제하고 같은 이름으로 다시 진행" 또는 "다른 이름으로 진행" 중
     하나를 선택하게 한다.
     - **삭제 후 진행**을 선택하면 동일한 `epub_path`로 `--force`를 붙여 재실행한다.
     - **다른 이름**을 선택하면 사용자에게 새 폴더 이름을 확인받아(예: 기존 이름에 접미사를
       붙인 값을 제안) `--dest-name <새이름>`을 붙여(`--force` 없이) 재실행한다.
   - **2, 3, 4, 5, 6**: 입력 자체의 문제(확장자 오류, 손상된 zip, 경로 이탈/정규화 충돌,
     암호화된 항목, 잘못된 대상 폴더명)다. stderr 메시지를 그대로 사용자에게 안내하고, 자동으로
     다른 옵션을 시도하지 않은 채 사용자의 다음 지시를 기다린다.
   - **8**: 압축 해제 도중 오류가 발생했지만 기존 상태로 복원됐다(정리까지 완전히 성공했으면
     잔존 파일 없음, 임시 폴더 정리만 실패했으면 그 경로가 메시지에 포함됨). 메시지를 사용자에게
     안내한다.
   - **9, 10, 11, 12**: 백업/복원/승격 자체가 실패한 예외적 상황이다. 자동으로 재시도하지 않고,
     stderr에 포함된 경로와 상태(예: 백업 폴더 위치, 복원 성공 여부)를 사용자에게 정확히
     안내한 뒤, 필요하면 수동 조치(예: 백업 폴더를 직접 원래 이름으로 되돌리기)를 안내하고
     사용자의 다음 지시를 기다린다.

## 2. 편집 대상 안내(추출 성공 후)

`extract`가 성공하면, 결과 폴더 안에서 다음을 시도해 사용자에게 편집 대상을 안내한다.

1. `<결과폴더>/META-INF/container.xml`을 읽어 `<rootfile full-path="...">` 속성값(OPF 문서의
   상대경로)을 찾는다.
2. 그 OPF 문서를 읽어 `<manifest>`의 `<item>` 중 다음에 해당하는 항목의 `href`를 모은다:
   콘텐츠 문서(`media-type="application/xhtml+xml"` 등), 스타일시트
   (`media-type="text/css"`), 내비게이션 문서(`properties="nav"` 또는
   `media-type="application/x-dtbncx+xml"`).
3. 모은 목록을 사용자에게 정리해 보여준다("이 파일들을 주로 편집하게 됩니다" 식으로).

`container.xml`을 찾을 수 없거나, OPF 경로를 찾을 수 없거나, 파싱에 실패하면 이 안내만
생략한다 — 대신 결과 폴더의 최상위 파일/폴더 목록을 보여준다. 이 실패는 `extract` 자체의
성공 여부(종료 코드 0)에 영향을 주지 않는다.

## 3. 편집

이후 사용자의 지시에 따라 압축 해제된 폴더 안의 파일(XHTML, CSS, OPF, NCX/nav 등)을 일반적인
파일 읽기/편집 도구로 수정한다. 이 스킬은 편집 내용 자체를 자동화하거나 검증하지 않는다 —
콘텐츠가 유효한 epub 문법을 따르는지는 사용자와 Claude의 책임이다.

## 4. epub 재압축(저장)

1. 사용자가 편집을 마쳤다고 알리면, 먼저 저장할 epub 경로를 사용자에게 확인한다(기본 제안값은
   원본 epub 경로 — 즉 덮어쓰기).
2. 먼저 `--force` 없이 실행한다:
   ```
   python <스킬폴더>/scripts/epub_tool.py pack "<folder_path>" "<output_epub_path>"
   ```
3. 종료 코드에 따라 처리한다:
   - **0(성공)**: stdout에 출력된 저장 경로를 사용자에게 안내한다.
   - **15(저장 대상에 이미 파일 존재)**: 덮어쓸지 사용자에게 확인한다.
     - **승인**하면 동일한 인자에 `--force`를 붙여 재실행한다.
     - **거부**하면 사용자에게 새 파일명/경로를 확인받아(`--force` 없이) 재실행한다.
   - **13(필수 컨테이너 파일 없음/mimetype 내용 오류)**, **14(저장 대상이 편집 폴더 내부)**:
     자동으로 옵션을 바꿔 재시도하지 않는다. 13은 편집 폴더 자체의 문제(예: `mimetype`을
     실수로 지웠거나 고쳤음), 14는 저장 경로를 편집 폴더 밖으로 다시 지정해야 하는 문제이므로,
     원인을 그대로 안내하고 사용자의 다음 지시를 기다린다.
   - **16**: 재압축 중 오류. 기존 파일(있었다면)은 보존됨을 안내한다.

## 주의 사항

- 이 스킬은 사용자 자신이 소유·선택한 로컬 epub 파일만 대상으로 한다. 출처가 불분명하거나
  적대적으로 조작됐을 수 있는 epub의 안전성은 보장하지 않는다(경로 이탈·대소문자 충돌·암호화
  항목 검사는 항상 수행하지만, 압축 폭탄 등 자원 고갈 공격에 대한 전용 방어는 없음).
- DRM이 적용된 epub은 지원하지 않는다.
- epub 콘텐츠(OPF/XHTML/CSS 등) 자체의 유효성 검증(`epubcheck` 수준)은 하지 않는다 — 이 스킬이
  보장하는 것은 OCF(zip 컨테이너) 패키징 규칙 준수까지다.
- 자세한 요구사항과 설계 근거는 `tools/epub_editor/docs/PRD.md`, `tools/epub_editor/docs/SRS.md`
  참고.
